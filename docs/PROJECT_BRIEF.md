# Project Brief: AI Agents Orchestrator

## Проблема

Техлид/архитектор, который проектирует модули и делегирует реализацию AI-агентам (Claude Code), вынужден работать последовательно: создал дизайн → сгенерировал план → вручную просил агента реализовать пункты один за другим → вручную коммитил → чистил контекст → повторял. Вся работа происходит в терминале на одном устройстве. Нельзя параллельно проектировать новый модуль, пока агенты реализуют текущий. Нельзя начать продумывать идею с телефона в дороге. Контекст теряется между сессиями — нужно заново объяснять агенту, на чём остановились. В результате человек, способный проектировать 3-5 модулей одновременно, становится бутылочным горлышком, потому что инструмент заставляет его работать последовательно. Боль оценивается на 8 из 10 и возникает ежедневно.

## Пользователь

Техлид или архитектор, который сам не пишет код, а проектирует модули и функции, затем делегирует реализацию AI-агентам. Активно использует Claude Code как основной инструмент разработки. Работает в движении — идеи приходят в дороге, на встречах, вне рабочего места, и хочет тут же начать прорабатывать их с агентом. До сих пор использовал только Claude Code в терминале — без дополнительных тулов для оркестрации или управления агентами. Главная потребность — параллельность: проектировать несколько модулей одновременно, пока агенты реализуют предыдущие, и не быть привязанным к одному устройству. Важна персистентность контекста — возможность уйти на два дня и вернуться к диалогу с агентом без потери нити.

## Решение

Адаптивное веб-приложение для управления полным циклом разработки через AI-агентов. Пользователь инициирует создание дизайна модуля — открывается диалог с агентом, который через структурированный скилл (вопрос за вопросом) помогает сформировать документ дизайна. Агент видит все существующие документы и исходники проекта для формирования полного контекста. Готовый дизайн можно просмотреть и попросить агента подправить. Из дизайна генерируется план реализации, который проходит ревью с возможностью правок. После утверждения плана агенты начинают параллельно работать над пунктами — система сама управляет коммитами и чисткой контекста. Агенты проводят взаимное ревью кода и могут запрашивать изменения друг у друга. После завершения реализации открывается pull request, где пользователь проводит финальное ревью и может запросить правки — агент вносит их отдельными коммитами. Дашборд показывает все модули, их стадии, дизайны, планы и артефакты процесса (логи тестов и т.п.). Ключевое отличие от работы в терминале — пользователь может параллельно вести несколько модулей на разных стадиях и делать это с любого устройства.

## Границы MVP

**Входит:**

- Интерактивное создание дизайна — чат с агентом через структурированный скилл, персистентность контекста между сессиями, просмотр и правки готового документа
- Генерация плана реализации — из готового дизайна, ревью и правки плана через диалог с агентом
- Параллельная реализация агентами — автоматические коммиты, управление контекстом, взаимное ревью кода между агентами, прогон тестов
- Дашборд — все модули, их стадии, дизайны, планы, логи тестов и другие артефакты процесса
- PR и ревью — автоматическое открытие pull request, запрос правок через интерфейс, внесение правок агентом отдельными коммитами
- Адаптивный веб-интерфейс — работает на десктопе и мобильных устройствах

**Не входит (на потом):**

- Нативное мобильное приложение
- Push-нотификации о завершении процессов
- Командная работа — несколько человек над одним проектом
- Поддержка других агентов и open-weights LLM (сейчас только Claude Code)

**Зависимости и интеграции:**

- Claude Code (по подписке, не по токенам)
- GitHub/GitLab — коммиты, PR, репозитории
- Файловая система проекта — агенты должны видеть исходники и документы

## Критерии успеха

Пользователь открывает браузер на любом устройстве, нажимает "Создать дизайн" и в диалоге с агентом формирует документ нового модуля. Параллельно в дашборде видно, как агенты реализуют два других модуля — коммитят, прогоняют тесты, ревьюят код друг друга. Пользователь может прерваться, вернуться через день с телефона и продолжить диалог с агентом с того же места. Когда реализация одного из модулей завершена, появляется pull request — пользователь проводит ревью, запрашивает правки, агент вносит их, и PR мёржится. Маркер успеха: пользователь одновременно ведёт 3 модуля на разных стадиях (дизайн, реализация, ревью) вместо одного последовательного потока — и делает это с любого устройства через адаптивный веб.
